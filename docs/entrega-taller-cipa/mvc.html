Avance MVC del proyecto final

Aplicación del patrón Modelo–Vista–Controlador al software odontológico MT Odontología, implementado con Django 5 (Python), plantillas HTML y CSS.

1. ¿Qué es MVC en este proyecto?

MVC separa los datos clínicos y de agenda (Modelo), la interfaz que ve el usuario (Vista) y la lógica que recibe la petición y decide qué hacer (Controlador).

Modelo
models.py / BD
↔
Controlador
views + forms + services
↔
Vista
templates HTML

En Django el patrón se llama a menudo MTV (Model–Template–View): la “View” de Django actúa como el Controlador clásico, y el Template es la Vista. En esta entrega usamos los nombres académicos MVC alineados con el código real.

2. Correspondencia con el código

Capa MVC En Django / este proyecto Ejemplo odontológico
Modelo app/models.py + MySQL/SQLite Cita, Paciente, Profesional, Sede, Disponibilidad
Vista app/templates/…/*.html + base.css mis_citas.html, agenda, panel profesional, formularios
Controlador views.py + forms.py + services.py + urls.py Crear cita, cancelar, confirmar, publicar horarios, elegir sedes

3. Caso de uso: agendar una cita

  1. Vista: el paciente ve el formulario HTML de “Agendar cita”.
  2. Controlador: la vista Django recibe el POST, valida el formulario y llama al servicio create_cita.
  3. Modelo: se guarda un registro Cita con estado pendiente, profesional, paciente y fecha.
  4. Vista de resultado: mensaje de éxito y redirección a Mis citas.
# Flujo simplificado (Controlador)
def solicitar_cita(request):
  form = CitaForm(request.POST or None)
  if form.is_valid():
    create_cita(...)  # reglas: solape, duración, disponibilidad
    messages.success(...)
    return redirect("mis_citas")
  return render(request, "citas/solicitar.html", {"form": form})

4. Apps del proyecto (dominios)

accounts

Autenticación: login, registro paciente/profesional, centros médicos.

perfiles

Paneles por rol, edición de perfil, gestión administrativa.

citas

Agendar, cancelar, reprogramar, agenda y estados de la cita.

clinica

Sedes, consultorios, especialidades y disponibilidad horaria.

historia / facturación / comunicación

Historia clínica, odontograma, facturas, notificaciones y reseñas.

core

Chrome público: base.html, CSS compartido, página de inicio.

5. Modelo: entidades principales

  • Paciente / Profesional: datos de persona y rol (grupo Django).
  • Cita: fecha-hora, motivo, estado (pendiente → confirmada / cancelada / atendida / no asistió).
  • Sede y AsignacionSede: dónde atiende el especialista.
  • Disponibilidad: franjas publicadas por día y hora.
  • Historia clínica / odontograma / recetas: datos sensibles de salud.

Las reglas de negocio (quién cancela, solapes, transiciones de estado) viven en services.py, no en la plantilla.

6. Vista: interfaz HTML

  • Todas las pantallas extienden core/templates/core/base.html.
  • Estilos con tokens CSS en core/static/css/base.css.
  • Textos de la interfaz en español; un botón principal por pantalla.
  • Navbar distinta por rol: el paciente no ve Agenda; el profesional no ve Mis citas.

7. Controlador: responsabilidades

  • Autorizar: decoradores login_required, paciente_required, profesional_required.
  • Validar entrada: formularios Django (Form / ModelForm) con CSRF.
  • Aplicar reglas: servicios como create_cita, asignar_sedes, publicar_franjas.
  • Responder: renderizar HTML o redirigir con messages.success / messages.error.

8. Diagrama de secuencia (resumen)

  1. Usuario → navegador (Vista HTML).
  2. Navegador → URL Django (urls.py) → función en views.py (Controlador).
  3. Controlador → Formulario → Servicio → Modelo ORM → base de datos.
  4. Controlador → plantilla HTML actualizada (Vista).

Ejemplo reciente del proyecto: al registrar un centro médico (formclinic), el controlador guarda el interés y publica una Sede para que el profesional la elija desde un modal en su panel, sin cambiar de pantalla.

9. Avance logrado (estado del proyecto)

  • Autenticación y roles Paciente / Profesional / Administrador.
  • Agenda de citas con estados y validación de solapes.
  • Sedes, horarios y panel profesional con modales HTML.
  • Historia clínica, facturación, notificaciones y verificación de profesionales.
  • Despliegue preparado (gunicorn, WhiteNoise) y pruebas con pytest.
